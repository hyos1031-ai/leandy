- **만들 것**: A사 OS · B사 OS (직원용) + 대표용 통합 대시보드 (린디 전용)
- **가장 가까운 선배 사례**
  - **비제이**(건설 대표, 앱 18개 → 프로젝트 허브)
  - **타코**(여러 회사 운영, 등급별 사내 인트라넷)
  - **로밍**(회사 4곳 통합 대시보드)
  - **제프**(구글 워크스페이스 안에서 만든 월요일 현황판)
- **린디가 이미 가진 부품**
  - ① 휴가 관리 OS: 구글 폼 → 시트 → 텔레그램/메일 결재 → 캘린더 → 연차 차감. 야생스터디 2회차에 만들었어요.
  - ② 현장사진 → 포트폴리오 워크플로우 (3회차) → **PROJECT 칸** (우리 회사 시안 · 현장사진은 프로젝트 기록)
  - ③ AI OS 구조도 6칸 (2회차)
- **결론**
  - 새로 다 만들 필요가 없어요. **휴가 OS가 이미 "PEOPLE 칸 1호 부품"**이에요.
  - 같은 방식(구글 워크스페이스 + Apps Script + 텔레그램 승인)으로 **PROJECT 칸 1개만 더 만들고**, 둘을 **프로젝트 번호와 직원 탭**으로 묶은 뒤 그 위에 대시보드를 얹으면 돼요.

## 2. 꼭 볼 회사 OS 사례 7개 (시스템 · 내용 · 워크플로우)

### ① 비제이(1조) — 프로젝트 허브 + 분류 OS · 건설 대표
- **시스템**
  - 앱 18개(근태, 공사, 납품, 수금, 현장일지, 회의록, 서류)를 **프로젝트 번호 하나**로 묶었어요.
  - 프로젝트 49건에 별칭 350개를 정리해, 앱마다 다르게 부르던 같은 공사 이름을 하나로 맞췄어요.
  - 공통 모듈(17/18개 앱 적용), 공유 인증, 이메일 로그인 한 번으로 포털에 들어가요. 앱마다 쓰던 PIN은 없앴어요.
- **내용**
  - 프로젝트 카드 한 장에 계약 · 시공 · 자재 · 정산 · 납품 건수가 보여요.
  - 상세 탭: 개요, 진행 체크, 간트, 공사, 수금, 정산, 자재, 회의록, 서류함, 타임라인(6개 앱 267건을 날짜순으로)
- **워크플로우**
  - 기존 시트는 **읽기 전용**으로 연결해요.
  - GitHub에 올리면 테스트 주소에 자동 반영 → 확인 후 정식 배포 → 문제가 생기면 되돌리기(정식 144 · 테스트 266 · 롤백 2)
  - NAS가 10분마다 점검 · 백업해요.
- **교훈**
  - 처음 4개월은 복사 · 붙여넣기로 수동 배포했어요(392번).
  - Apps Script 화면은 열리는 데 2~4초 걸렸는데, NAS로 옮기니 0.3~0.5초가 됐어요.
  - 분류 규칙은 같은 폴더로 채점하면 과적합이 생겨요. **새 폴더로 독립 시험**해야 해요.
- **린디에게**: 업종이 제일 가까워요(건설 · 현장 · 서류). "프로젝트 번호 + 별칭 정리"와 "읽기 전용 연결"을 그대로 가져오세요.

### ② 타코(1조) — 등급별 사내 인트라넷 · 여러 회사 운영
- **시스템**: 한 번 로그인하면 **내 등급에 맞는 업무 앱만** 보여요.
- **앱**: 공지, 직원 승인 관리, 내 캘린더, 업무현황판, **전자결재(근태 · 연장근무)**, 부서별 앱, 주간회의록, 재무회계
- **워크플로우**
  - 수주통보서 한 장 → 모든 팀 확인 → 출하 → PL → CI → 선적
  - 막는 규칙이 제일 쓸모 있었대요. 예) PL 전에는 CI를 못 쓰고, 수량이 다르면 확정이 안 돼요.
- **2회차 OS 지도**
  - 회사마다 OS가 달라서 **회사별 · 업무별로 지도를 따로** 그렸어요.
  - 아침 시작 화면은 **회사별 카드 + 오늘 급한 것**이에요.
- **야생 2회차**
  - Aside가 이카운트에서 구매현황 엑셀을 받아 오고, Claude Code가 **지난번보다 비싸게 산 건**을 찾아요(4,417건 중 175건).
  - 결과는 **회사 안에서 볼 판 / 밖에 낼 판** 두 벌로 만들어요.
- **린디에게**
  - 회사 2곳 구조와 등급별 화면은 타코 방식이 정답에 가까워요.
  - 사인 제작 자재 구매 단가 체크는 BID & COST 칸에 그대로 쓸 수 있어요.

### ③ 로밍(4조) — 회사 4곳 + 내 하루 통합 대시보드
- **시스템**: 박스 8개(위 4개는 개인, 아래 4개는 회사). 회사마다 대시보드가 따로 있고, 통합 화면은 **요약만 가져와요**.
- **회사 박스 공통**
  - 돈 요약 + 오늘 할 일 / 7일 안 / 이메일 탭
  - 아침마다 텔레그램 알림, 체크해야 멈춰요.
  - 세무 일정은 자동으로 할 일에 올라가요.
- **교훈**
  - 로그인 · 저장 같은 바탕을 먼저 만들었어요.
  - 박스 하나를 완성한 뒤 본떠서 나머지를 만들었어요.
  - 올리기 전에 최신 파일 받기, 체크 상태는 클라우드에 저장하기, 실패하면 알리기
- **린디에게**: 대표용 통합 대시보드의 모델이에요.

### ④ 제프(4조) — 회사 월요일 현황판 PRD
- **시스템**: Supabase 없이 **회사 구글 워크스페이스 안에서만** 만들어요. 구글 폼 → 시트 → Apps Script 웹앱이고, 로그인은 회사 구글 계정이에요.
- **내용**
  - 팀별 신호등이 자동으로 바뀌어요. 담당자가 보정할 수 있지만 이유 한 줄이 필수예요.
  - 매출 대 목표, **지난주 "다음 주 할 일"을 이번 주 폼에 다시 띄워** 했다 / 일부 / 못 했다로 답하게 해요.
- **원칙**: "**내가 모으지 않아도 차 있는 판**". 예전 대시보드는 갱신이 대표 손에만 달려 있어서 멈췄대요.
- **린디에게**: 린디의 휴가 OS와 **같은 기술 조합**이에요. 직원 주간 업무 보고를 이 방식으로 받으면 PEOPLE의 "업무 성과"가 저절로 쌓여요.

### ⑤ 마틴(3조) — 측정 → 대시보드 → 승인 후 카톡 보고
- **워크플로우**
  - 새벽에 측정 · 캡처 · 보고문까지 끝내 둬요.
  - **내 카톡으로 미리보기**가 오고, "진행해"라고 답한 날만 병원별 카톡방에 보고가 나가요.
  - 휴가 중이거나 보고 요일이 아니면 규칙대로 보류해요.
- **린디에게**: 대표 승인이 필요한 일(견적 발송, 고객 보고, 공문)을 이 방식으로 처리하세요. 이미 만든 텔레그램 승인과 같은 원리예요.

### ⑥ 크리스(6조 · 야생 2회차) — facet: 광고주별 정산 웹
- **시스템**: 영수증을 여러 장 한꺼번에 올리면 날짜와 금액을 자동으로 읽어요. 처리할 일 화면이 있고, 담당자 · 프로젝트 등록 신청은 관리자가 승인해요.
- **Aside 역할**
  - 배포한 웹을 **실제 사용자처럼 열어 검토**하고 개선점 17개를 P0 · P1 · P2로 나눴어요.
  - 사용자별 매뉴얼 3종(관리자 · 회계사무실 · 영수증 올리는 사람)을 만들었어요.
- **린디에게**: 현장 경비와 외주 정산 칸의 모델이에요. "직원용 매뉴얼은 Aside가 만든다"는 점도 그대로 쓸 수 있어요.

### ⑦ 레이(4조) — 새싹 교육 운영 OS (팀 웹앱)
- **시스템**
  - 팀 초대 코드가 있어야 가입할 수 있어요.
  - 노션 업무 36건을 표와 칸반으로 보여 주고, D-day가 자동으로 계산돼요.
  - 문서는 노션과 드라이브에 그대로 두고, **OS에는 상태 · 일정 · 담당 · 링크만** 둬요.
- **린디에게**: "원본 파일은 NAS · 드라이브에 그대로, OS는 목록과 상태만" 원칙을 가져오세요. 같은 걸 두 번 적지 않게 돼요.

## 4. 저장소에서 반복해서 나온 설계 원칙 10개

1. **프로젝트 번호가 모든 연결의 열쇠** (비제이, 린디 2회차): `A-2611-01`, `B-2611-01`처럼 회사 머리말을 붙여요.
2. **원본은 하나, 나머지는 읽기만** (린디 CLAUDE.md, 비제이, 어메일): 대시보드는 시트를 고치지 않아요.
3. **④ 사람이 확인하는 자리**: 보내기 · 승인 · 금액은 미리보기 → 확정 2단계로(마틴, 린디 휴가 OS, 제프 Discord 「진행」).
4. **⑤ 쌓여서 나아지는 장치**: 장부와 채점을 남기고, 다음 판을 시작하기 전에 먼저 읽게 해요(양세, 치코, 차차, 아람).
5. **모르면 "확인 필요"**: 지어내지 않아요(유스, 타코 2배 이상 변동 제외, 영미 "빈칸은 동의가 아니다").
6. **입력은 담당자가, 화면은 자동으로** (제프): 대표가 모아야만 돌아가는 판은 멈춰요.
7. **두 벌 만들기**: 회사용과 밖에 낼 판을 따로. 공유용 캡처는 화면은 그대로 두고 데이터만 가상으로.
8. **하네스 = 매번 하던 말을 파일로**: 폴더마다 `CLAUDE.md` 규칙 + 루틴 + 다음 작업(린디, 봄, 크니, 버블)
9. **버전마다 하나만 바꾸기** (5회차 가이드): v1 → v2 → v3, `개선기록.md`에 한 줄씩 남겨요.
10. **쓰이게 만들기** (배짱 10_쓰이게_만들기)
    - 설명하지 말고 직원 요청 옆에 결과를 놓아 보여 주세요.
    - 파일럿은 2명으로 하고, 불평을 받는 게 목표예요.
    - "칭찬이 돌아온다"는 아직 안 쓰고 있다는 신호일 수 있고, "수정 요청이 온다"가 쓰고 있다는 신호예요.

## 5. 기술 선택: 단계별로 키우기

| 단계 | 조합 | 사례 | 언제 |
|-|-|-|-|
| **1단계 (지금)** | 구글 폼 + 시트 + Apps Script + 텔레그램/Gmail | 린디 휴가 OS, 제프 현황판, 유이 승인 시트 | 직원 수가 적고 무료로 빨리 시작할 때 |
| 2단계 | Apps Script 웹앱으로 대시보드 화면 + clasp + GitHub 비공개 저장소 | 제프, 봄 | 화면을 보기 좋게 만들고, 코드를 버전 관리할 때 |
| 3단계 | Next.js 웹앱 + Supabase(로그인 · RLS) + Cloudflare Workers | 와니, 어메일, 레이 | 직원별 권한이 복잡해지고 화면이 느려질 때 |
| 4단계 | 사내 NAS 서버 + 공통 모듈 포털 | 비제이, 타코 | 앱이 많아지고 속도와 사내 보관이 중요할 때 |

**주의**
- Vercel 무료 플랜은 비상업용이에요(와니 확인). 회사용은 Cloudflare Workers를 쓰세요.
- 회사 메일이 구글이 아니라 캘린더 공유는 `.ics` 첨부로 우회했어요.
- NAS 경로는 Aside 보안 모드에서 막혀요. 작업폴더에 zip으로 넘기세요(린디 3회차).
