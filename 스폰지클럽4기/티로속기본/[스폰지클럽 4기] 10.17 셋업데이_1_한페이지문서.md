# [스폰지클럽 4기] 10.17 셋업데이

2026년 10월 17일, 스펀지 클럽 4기 셋업 데이가 온라인으로 진행되었다. 이번 세션은 스펀지 클럽의 배경과 세계관 소개, 6주 과정 운영 방식 안내, GitHub 실습, 바이브 코딩 입문 시연, 그리고 블로그 자동화 워크플로우 심화 공유로 구성되었다. 운영진 제외 총 73명이 신청하였으며, 이는 역대 최다 참여 기수로 기록되었다.

## 스펀지 클럽 소개 및 세계관

스펀지 클럽은 스펀지밥의 세계관에서 오마주를 따온 프로그램으로, "좋은 물이 흐르는 바다에서 월요일이 기다려지는 사람들"이 모여 누구도 빼앗을 수 없는 자신만의 워크플로우를 만드는 것을 목표로 한다. 세 가지 기둥은 **주체적인 개인**, **도메인 지식·경험·스토리**, **밴드(크루 집단)**이며, 이를 바탕으로 여섯 가지 핵심 가치를 운영한다.

- **주체성**: 주도성과 구별되는 개념으로, AI와 협업하더라도 최종 선택권과 의사결정권은 본인에게 있어야 한다.
- **이기적 공유**: 60% 수준에서 공유를 시작해 100%로 완성하는 방식. 공유 행위 자체가 자신의 지식을 정제하는 과정이다.
- **안전한 공간**: 모르는 것을 자유롭게 질문할 수 있되, 타인의 결과물을 참고했을 경우 반드시 **샤라웃(출처 공유)**을 해야 한다.
- **냅다 정신**: 일단 시작하고, 만든 후에도 계속 굴리며 키워나가는 태도.
- **크루**: 6주 과정에서 만나는 동료들이 AI 학습을 넘어 삶의 여정에서도 중요한 크루가 될 수 있다.
- (묵시적 여섯 번째) 서로의 성장을 응원하고 지지하는 문화.

ChatGPT가 한국에 도입된 것은 2023년 1월로, 현재(2026년 10월 기준) 약 3년 9개월이 경과했다. 이 속도의 변화는 인류 역사상 전례 없는 수준이며, 따라서 "모르는 것이 정상"이라는 인식을 바탕으로 낯섦에 익숙해지는 것이 스펀지 클럽의 출발점이다.

## AX 워크플로우와 해자 개념

**워크플로우**는 결과물이 나오기까지의 전 과정을 의미한다. 같은 서류를 만들더라도 사람마다 과정이 다르며, 스펀지 클럽 4기는 그 과정 자체를 공유하는 것을 핵심으로 삼는다.

**해자(垓字)**는 차별성을 의미하며, AI 워크플로우에서 해자가 성립하려면 명확한 **비포·애프터**가 있어야 한다. 구체적으로는 비용 절감, 아웃풋 증가, 수익 증대, 신청자 수 증가 등이 해당한다. 해자가 실질적 임팩트를 갖기 위한 두 가지 조건은 다음과 같다.

- **내 도메인에 붙어 있을 것**: 내가 잘 아는 분야, 내가 고민하던 문제에 연결된 워크플로우여야 한다.
- **루프(반복 개선)**: 한 번 만들고 끝이 아니라, 쓰면서 계속 고쳐나가는 과정이 해자를 만든다.

워크플로우를 만드는 과정에서 겪는 비효율 구간은 필연적이며, 그 삽질 경험 자체가 AI 시대의 해자라는 관점이 강조되었다. 동네 치과 원장이 바이브 코딩으로 보험 대조, 상담 기록, 해피콜 등 병원 전체 시스템을 AX화한 사례가 소개되었으며, 초기 비용이 1억 원 이상 들었다는 댓글 논란에 대해 "비효율 구간을 통과하지 않고 이를 구축할 수 있는 사람은 없다"는 시각이 제시되었다.

## SaaS 환경 변화와 나만의 소프트웨어

SaaS(Software as a Service)는 소프트웨어를 서비스로 판매하는 구조로, Zoom·Slack·Notion 등이 대표적이다. 그러나 바이브 코딩으로 누구나 유사 기능을 만들 수 있게 되면서 SaaS 기업들의 단가가 급락하고 있다. 2026년 1분기 앱스토어 신규 등록은 전 분기 대비 84% 증가했으나, 10만 다운로드를 넘긴 비율은 여전히 낮다. 소프트웨어 주가 시가총액은 2월 기준 1조 달러 이상 하락했으며, Adobe 역시 가격 인상 등 어려움을 겪고 있다.

이러한 환경에서 **나만의 소프트웨어(맞춤형 에이전트)**를 만들어야 하는 이유는 다음과 같다.

- 매번 같은 결과가 필요한 반복 작업에 적합하다.
- 여러 에이전트를 연결해야 하는 복합 워크플로우에 필수적이다.
- 내 데이터를 직접 활용할 수 있다.
- UI/UX를 맞춤형으로 설계할 수 있다.
- 제작 비용이 매우 저렴하다.

4기 목표는 **1인 최소 1개의 워크플로우 완성**이며, 욕심을 내면 2개 이상도 가능하다.

## GitHub 실습

셋업 데이의 핵심 실습으로 GitHub 사용법이 안내되었다. 주요 개념은 다음과 같다.

- **레포지토리(Repository)**: 파일과 폴더를 담는 저장소 단위.
- **클론(Clone)**: 원격 레포지토리를 내 PC로 통째로 내려받는 것.
- **커밋(Commit)**: 변경 사항을 기록하는 행위.
- **푸시(Push)**: 내 로컬 작업물을 원격(GitHub)으로 올리는 것.
- **풀(Pull)**: 원격의 최신 내용을 내 로컬로 당겨오는 것.
- **브랜치(Branch)**: 원본(main)을 건드리지 않고 별도로 작업하는 가지.
- **PR(Pull Request)**: 브랜치 작업을 main에 합쳐달라는 요청서.

실습 순서는 ① Claude Code 실행 → ② 로컬 폴더(`claude-project/sponge-club-4`) 생성 및 연결 → ③ GitHub 레포지토리 주소 복사 후 "클론해 줘" 명령 → ④ 자기소개 MD 파일 작성 → ⑤ 커밋 및 푸시였다. Claude Code와 GitHub 간 인증이 필요한 경우, Claude in Chrome 확장 프로그램을 활용하거나 "컴퓨터 유즈(Computer Use)"를 통해 해결하도록 안내되었다. 구글 드라이브 등 클라우드 동기화 폴더는 충돌 위험으로 인해 사용이 권장되지 않는다.

## 바이브 코딩 입문: 쓱싹 제작 사례 (비비안)

비개발자가 Claude Code와의 대화만으로 1시간 만에 파일 정리 앱 **"쓱싹"**을 제작한 과정이 시연되었다. 쓱싹은 지정 폴더의 파일을 오래된 순서대로 보여주며, 스와이프(틴더 방식)로 삭제·보관·보류를 결정하고, 포인트와 리워드(미피 캐릭터 활용)로 동기를 부여하는 맥 전용 앱이다.

프롬프트 작성 시 **STIC 기법**이 소개되었다.

- **S(Situation)**: 내가 어떤 사람이고 무엇이 불편한지.
- **T(Task)**: AI가 해야 할 일.
- **I(Intent)**: 진짜 바라는 모습, 만들고자 하는 의도.
- **C(Concern)**: 걱정되는 점, 미리 체크해야 할 사항.

제작 과정의 7가지 팁은 다음과 같다.

1. STIC 프롬프트로 시작하기.
2. PRD(Product Requirements Document, 기획 설계서)를 먼저 작성하고 개발 시작하기.
3. 타임랩스(음성 입력 도구)를 활용해 자연어로 자유롭게 말하기.
4. 레퍼런스를 막 던지기 (이름 몰라도 설명으로 충분).
5. PNG 구조도로 Claude와 싱크 맞추기.
6. Claude에게 끌려가는 신호(무의식적 "응 진행해", 수정 내용 설명 불가, 원치 않는 기능 추가) 감지 시 즉시 멈추고 질문하기.
7. MVP(핵심 기능 하나)부터 만들고 이후 살을 붙이기.

**PRD**는 무엇을 왜 만드는지 적어둔 설계도로, Claude Code가 개발 중 지속적으로 참조하는 문서다. 오늘 과제는 제공된 인터뷰 스킬을 활용해 PRD를 작성하고 GitHub에 푸시하는 것이다.

## 블로그 자동화 워크플로우 심화 (K)

블로그 자동화는 수익 창출을 목표로 하는 어필리에이트(제휴 마케팅) 기반 워크플로우다. 핵심 원칙은 **"AI에게 반복 작업을 매일 시키지 말고, 그 일을 대신하는 프로그램을 AI로 만들어라"**이다. 이를 통해 토큰 비용을 최소화하고, AI 없이도 프로그램이 독립적으로 작동하게 한다.

**글감 선정 4가지 기준(키워드 저울)**

- **경쟁력**: 내 글이 상위 노출될 수 있는가 (경쟁 글 수 대비 검색량).
- **트렌드**: 지금 뜨고 있는 키워드인가 (네이버 크리에이터 어드바이저 활용).
- **시즌**: 작년 같은 시기에 떴던 키워드인가 (전년도 데이터 비교).
- **현금성**: 수요는 높고 공급(경쟁 글)은 적은 황금 키워드인가.

네이버 검색 API, 데이터랩 API 등 무료 API를 활용해 검색량·경쟁 글 수를 자동으로 수집하며, 브라우저 에이전트를 통해 Perplexity 등 유료 API 없이도 리서치를 수행한다. 글 작성 후에는 Python 기반 룰베이스 프로그램으로 광고 표시 여부, 제목 키워드 포함 여부, 글자 수 초과 여부, 가격 정보 출처 확인 등을 자동 검수한다.

**오르카(Orca) + 테일스케일(Tailscale) + 멀티카(Multika) 조합**을 통해 외부(모바일·다른 PC)에서도 홈 컴퓨터의 에이전트를 원격 제어할 수 있으며, 멀티카의 칸반보드 방식으로 작가·편집장·디자이너·링크 관리자 등 역할별 에이전트가 자율적으로 협업하는 오토파일럿 구조를 구현하고 있다. 현재 글 기획·작성·검수·발행 예약까지 대부분 자동화되어 있으며, 550만 원짜리 유럽 크리스마스 마켓 패키지 여행 상품 판매로 약 16만 원의 수익을 달성한 사례가 공유되었다.

## 4기 운영 구조 및 향후 일정

- **정규 세션**: 8회차, 매주 워크플로우 제작 과정 공유 및 미션 제공.
- **유닛**: 관심사별 소그룹(5개 이상 예정), 선택 참여이며 지원 방식으로 운영. 유닛 과제 미제출 시 탈락.
- **스폰지 공유회**: 기수 내 이기적 공유 세션.
- **오프라인 모임**: 10월 31일, 삼성역 인근 (오전·오후반 분리 운영).
- **스타터 키트**: 5종 예정, 내일(10월 18일) 제공.
- **자료 공유**: 다시 보기·발표 자료·속기본은 공유 스프레드시트에 업로드.
- **크루챗**: 추후 개설 예정.

오늘 과제는 인터뷰 스킬을 활용해 나만의 소프트웨어 PRD를 작성하고 GitHub 과제 레포지토리에 푸시하는 것이다. 다음 주까지는 본인의 SaaS, 블로그, 또는 GEO 관련 소프트웨어 중 하나를 간단하게 구현하는 것이 목표다. 처음 만드는 결과물은 비효율적인 것이 당연하며, 포기하지 않고 8회차까지 함께 완주하는 것이 권장되었다.
